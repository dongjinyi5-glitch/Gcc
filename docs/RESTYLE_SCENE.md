# restyle_scene v2 —— 场景贴图的程序化重彩化

> 一句话结论：**能用，但只是 ImageGen 缺席期间的兜底。**
> 它守得住几何、碰撞与烘焙光照（alpha 逐位相同、L\* 基本不动），
> 守不住笔触——它做的是"把渲染图的配色换成矿物颜料"，不是"重画一张画"。

脚本：`tools/scripts/restyle_scene.py`
产物：`art/scene_restyle/`（单图预览、全库缓存、前后对比）
全库重绘：`python restyle_scene.py level all` → `art/scene_restyle/all/`（1450 张唯一贴图）
整关合成：`python scene_render.py <level> --restyled art/scene_restyle/all`

---

## 1. 契约（不可破的两条）

| 不变量 | 为什么 | 实测 |
|---|---|---|
| **alpha 逐位相同** | 剪影就是碰撞与网格契约；改一个像素的透明就等于改物理 | 8/8 预览贴图 `np.array_equal` 通过 |
| **L\* 不被替换** | L\* 里装着烘焙好的光照图：灯光晕、窗光、L8 的火光。SCENE_PLAN 的硬约束是灯不能移位 | 暗贴图 dL 均值 ±0.5；亮贴图 −3～−4.6（墨线压暗，符合预期） |

只有 a\*、b\* 被改写。这是整个方案能成立的前提：**换色不换形，换色不换光。**

---

## 2. 六次失败，六次修正

这一节比结论有用。每一版都跑过 `preview` 并肉眼看图。

| # | 做法 | 结果 | 原因 |
|---|---|---|---|
| 1 | 复用 `restyle_ink`（按语义槽选色） | 砖墙变成蓝绿马赛克 | 场景没有"衣服/皮肤"这种槽位，默认槽是 garment |
| 2 | 每像素量化到最近矿物颜料 | 整个世界发绿 | 夜景被彩色灯光整体染色，最近颜料把**色偏**放大成"到处石绿" |
| 3 | 减中位色度 + 冷/暖双斜坡 | 一张琥珀色照片 | 中位数被近黑像素主导（≈中性），而所有**可见**表面都是琥珀色，减了个空 |
| 4 | 支点固定 L\*=42 的明度倾斜 | 整幅偏蓝 | 夜景中位亮度只有 4～13，所有像素都在支点之下 |
| 5 | 阴影提亮 sigma 14 / 强度 9 | 夜空从深藏青变成浅钢蓝，**夜没了** | 提亮伸进了 L\* 3～20 的天空，不只是真正的黑 |
| 6 | 石绿/朱红掩膜建在去色偏后的 a'/b' 上 | 气瓶变淡薄荷、幕布变橙褐、标题血变赭石 | 去色偏减掉的正是一个绿色/红色赖以成立的 b\*（+13→+3），掩膜值掉到 0.03 |

修正后的对应做法：

1. 光源估计用 **L\*² 加权的平均色度**（估的是灯的颜色，不是画面中位数）；
2. 校正量 **按亮度门控**（`lit = clip(L/42)`）——只有有光的地方才有色偏，否则会把几乎无彩度的暗部推成 b\* −9；
3. 倾斜支点用 **本图自己的中位 L\***——"比这张图更亮的地方算受光"，这才是想说的那句话；
4. 提亮收窄到 sigma 8、强度 7×0.15，只碰真正的黑；
5. 冷暖决策加 **gain 对比度**（2.2），因为赭石与石青线性五五混合是一坨灰——这正是"要么棕要么蓝、中间没有东西"的根源；
6. 绿/红掩膜改用 **去色偏之前**的 A/B，并给绿色加一条 L\* 70 以上的锥形衰减（汞灯是绿光，否则灯头会被画成石绿）。

## 3. 最终算法（七步）

```
sRGB → Lab
1. 光源估计  ill = Σ(L²·(a,b)) / Σ(L²)          仅不透明像素
   a' = a − cast·ill_a·clip(L/42)               亮度门控，cast=0.85
2. 双线索选斜坡
   w0 = 0.5 + b'/18 + tilt·(L − median_L)/40     tilt=0.30
   w  = clip((w0−0.5)·gain + 0.5, 0, 1)          gain=2.2，压成平涂色块
3. 冷暖斜坡查表（按 L*）
   ta,tb = cool(L)·(1−w) + warm(L)·w
4. 石绿 / 朱红掩膜（用**原始** A/B，不用去色偏后的）
   g0 = clip((−A−3)/8)·clip((B−3)/8)·clip((70−L)/25)
   r0 = clip((A−13)/18)·clip((B−7)/14)
   ta,tb 依次向 green(L) / red(L) 插值
5. 色度按 L*<11 收口（暗部饱和颜料超出 sRGB 色域）
   a₂ = a'·(1−chroma) + ta·chroma                chroma=0.85
6. 色块洗涤：对 (a₂,b₂) 做 r=2.5 盒式模糊，**L\* 不动**
7. 墨线 + 纸纹
   g = |∇ blur(L,1.2)|，L₂ = L₂·(1 − 0.55·clip(g/4.5))
   用**绝对阈值**（L\*/像素），不用分位数——分位数在柔焦贴图上一条线都不画
   零均值噪声乘性 ±3%
→ Lab → sRGB，alpha 原样带回
```

四条斜坡不是手调数字，而是"哪种颜料、在哪个 L\*"：

| 冷 | 花青 @12 → 石青 @46 → 石青 @70 → 纸 |
|---|---|
| 暖 | 赭石 @16 → 赭石 @40 → 藤黄 @62 → 纸 |
| 绿 | 石绿 @18 → 石绿 @52 → 纸 |
| 红 | 朱红 @26 → 朱红 @62 → 纸 |

a\*、b\* 直接取自 `restyle_ink.PIGMENTS`，所以场景与角色的调色板不可能漂移。
`python restyle_scene.py palette` 会打印每一档的最近颜料，用于自查。

**关键两条**：

1. 颜料彩度**不随变暗而衰减**。照片是这样，颜料不是——花青在 L\* 12
   和在 L\* 46 一样蓝。第一版让 a\*/b\* 向墨收敛，输出彩度只有 3～9（等于给渲染图
   套了个 LUT），这就是"洗白了"的根因。
2. **绿/红掩膜必须用去色偏之前的 A/B**。去色偏减掉的正是让绿色读作绿色的那个
   b\*（气瓶从 +13 掉到 +3，掩膜值 0.03），第一版结果是气瓶变淡薄荷色、
   幕布变橙褐。去色偏是为了归一化**冷暖**，不是判断**色相**。

## 5. 局限（必须说清）

1. **它不产生笔触。** 出来的是一张"配色被换成矿物颜料的渲染图"，不是国画。
   远处的整体观感成立，凑近看没有笔锋、没有飞白、没有墨的浓淡。
2. **平涂低对比贴图最差。** `Romp02`（整片铆接钢板）几乎没有色相信息，
   锈迹会被推成一块突兀的橙斑；而 `Boat008a`（机舱，管道多、明暗强）效果最好。
3. **色相只有四支。** 冷暖两支覆盖绝大多数材质，石绿/朱红靠"源图本来就绿/红"
   这一条窄掩膜补上（气瓶、青绿钢梁、血、幕布）。中间色相——紫色、青色、
   大面积的鲜艳蓝——没有对应的国画颜料，会被压到最近的支上。
4. **共享贴图会一起变。** `Quay_*` 同时在 L3/L4/L5，`Wheelhouse_01` 在 L3/L4。
   整库重绘时这不是问题（同一份缓存），但单独改一张要接受三关同时变。
5. **两处可接受的偏差**：亮部（L\* > 70）一律向纸靠，所以原图的蓝天会变浅；
   汞灯那种"绿光"会被判成石绿（已用 L\* 70 以上的锥形衰减压掉大部分）。

## 6. 写回游戏（L3 已写入）

脚本：`tools/scripts/patch_scene.py`（定点字节覆盖，不走 `env.save()`——那条路会
把这个 build 的 resources.assets 写坏，`writeback.py` 里留了失败记录）。

```
python patch_scene.py level3 --check      # 只报告，不动盘
python patch_scene.py level3 --apply      # 先备份再写
python patch_scene.py sharedassets4.assets --audit backup/pre_scene_<时间>/sharedassets4.assets
```

**L3 的 167 张贴图全部在 `sharedassets4.assets` 一个文件里。**

| 检查 | 结果 |
|---|---|
| 写回前 check | 167/167 编码器复现原像素块（不是"大概对"，是逐字节相等） |
| 写回后文件大小 | 244,336,532 B → 244,336,532 B（未变） |
| 差异字节落点 | 160,965,332 个差异字节，**100% 在像素块内，块外 0 个** |
| 从补丁后的包体重渲染 L3 | 与目标重彩全景**逐像素完全相同**（max diff 0） |

**一个此前没记录的坑**：L3 有 16 张贴图是 **format 3（RGB24）**，不是 ARGB32。
角色那批全是 format 5，所以"全部 ARGB32"这个结论只在角色集成立。RGB24 的字节序
同样是暴力枚举六种排列试出来的：R,G,B，行自下而上，3 字节/像素。

**回滚**：把 `backup/pre_scene_<时间>/sharedassets4.assets` 拷回 `ggc_Data/` 即可。
`backup/sharedassets4.assets`（2015-04-29）是原始未改动版本，一直没被覆盖。

**注意**：目前只写了 L3。其余 12 关仍是原版美术，所以进游戏会看到明显的关卡差异，
这正好用来判断"玩家能不能接受这套配色"。

## 7. 和 ImageGen 的分工（建议）

ImageGen 当前返回 `route config not found [gpt-image-2.5-sunburst]`，
最小提示词（白底红圆）也复现，**服务端模型路由缺失，已花 0 credits**。

所以建议按"面积"分工，而不是按"能不能自动"分工：

| 层 | 面积占比 | 做法 | 理由 |
|---|---|---|---|
| T1 地标 162 张 | 37.2% | **ImageGen 重绘** | 一眼能认出来的东西，必须真画 |
| 其余 1288 张 | 62.8% | **restyle_scene v2** | 观众不会盯着看，配色统一就够 |
| 碰撞贴图 273 张 | 4.1% 面积 | 两种都行 | 只有 4.1%，不影响预算 |

ImageGen 恢复后，只需补 162 张付费图；在此之前，v2 能让整关"先看起来是这套戏"，
用于验证历史改编、验证光照没坏、验证玩家不会觉得突兀。

**推荐**：先按这个分工推进。如果 ImageGen 长期不恢复，再评估把 T1 降到 60～80 张
（每关只挑 4～6 个真正的地标）。
